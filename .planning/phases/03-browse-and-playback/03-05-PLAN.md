  <action>
The root cause: Drizzle's `.default("(datetime('now'))")` in schema.ts generates a migration that wraps the SQLite expression in quotes, making it a string literal instead of a function call. The column stores the literal text `(datetime('now'))` rather than an evaluated timestamp like `2026-03-30 10:15:00`.

Fix approach — set createdAt explicitly at insert time (safest, no migration needed):

1. In backend/src/routes/assets.ts, find the `db.insert(assets).values({...})` call (around line 62-76). Add `createdAt: new Date().toISOString()` to the values object. The full values should include:
   ```ts
   .values({
     id: assetId,
     originalFilename: file.filename,
     filepath: `${assetId}/original${ext}`,
     fileSize,
     fileHash,
     status: 'ingesting',
     title: file.filename.replace(/\.[^.]+$/, ''),
     createdAt: new Date().toISOString(),
     metadataStatus: 'pending',
     thumbnailStatus: 'pending',
     transcriptionStatus: 'pending',
     searchIndexStatus: 'pending',
   })
   ```

2. In backend/src/db/schema.ts, update the createdAt and updatedAt defaults on the assets table to use `sql` template literal so future migrations generate correct SQL. Change:
   ```ts
   createdAt: text('created_at').default("(datetime('now'))"),
   updatedAt: text('updated_at').default("(datetime('now'))"),
   ```
   To:
   ```ts
   createdAt: text('created_at').default(sql`(datetime('now'))`),
   updatedAt: text('updated_at').default(sql`(datetime('now'))`),
   ```
   Also apply the same fix to the customFields table's createdAt default (line 48).

   Ensure `sql` is imported from 'drizzle-orm' at the top of schema.ts. Check existing imports first — it may already be imported.

Do NOT run db:generate or db:migrate — the schema default fix is for future migrations only. The explicit insert fix handles current behavior.

Note: Existing assets with the literal string will still show "Invalid Date". This is acceptable since this is a dev/testing environment and those records can be re-imported. If needed, a one-time SQL update could fix them: `UPDATE assets SET created_at = datetime('now') WHERE created_at = '(datetime(''now''))';` but this is not required for gap closure.
  </action>
