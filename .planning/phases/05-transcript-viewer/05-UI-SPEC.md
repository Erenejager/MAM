| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 14px | 400 | 1.5 | Fira Sans |
| Label | 12px | 400 | 1.4 | Fira Code (monospace) |
| Heading | 14px | 600 | 1.2 | Fira Sans |
| Segment text | 14px | 400 | 1.5 | Fira Sans |

Notes:
- Timecodes use `font-mono text-xs` (12px Fira Code) -- already established in TranscriptList.
- Tab labels use 14px weight 600 Fira Sans.
- Search input uses 14px weight 400 Fira Sans.
- Match counter uses 12px weight 400 Fira Sans, text-muted color.
- Font weights restricted to 400 and 600 only (per CLAUDE.md -- weight 500 is not used).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F0F23` | Background surfaces, search input background |
| Secondary (30%) | `#1E1B4B` | Detail panel background, tab bar background |
| Accent (10%) | `#E11D48` | Active segment left border, active tab indicator, focus rings |
| Destructive | `#E11D48` | Not applicable this phase (no destructive actions) |
| Match highlight | `#F59E0B` (amber) | In-transcript search match word highlighting |

Accent reserved for:
- Active transcript segment left border (2px)
- Active transcript segment background tint (`bg-cta/20`)
- Active tab underline indicator
- Focus-visible outlines on interactive elements
- Search input focus border

Match highlight details:
- Matched words within segment text: `bg-amber-500/30 text-amber-200` (amber background tint with light amber text)
- Current match (navigated-to): `bg-amber-500/50 text-amber-100` (stronger amber for the focused match)
- Amber chosen for contrast against Cinema Dark navy backgrounds and to not conflict with the CTA red accent

Visual anchor: Primary visual anchor is the active transcript segment (CTA left border + `bg-cta/20` tint). Secondary anchor is the tab bar with active CTA underline indicator.

## Interaction States

### Tab switching
- Clicking "Info" shows MetadataSection + CustomFieldsSection (current layout)
- Clicking "Transcript" shows search input + transcript segment list
- Video player remains pinned above tabs in both states
- `videoRef` must persist across tab switches (do not unmount VideoPlayer)
- Tab state is local component state (no URL routing)

### Search behavior
- Typing in search input highlights matching words within all segments
- All segments remain visible regardless of match status
- Match count updates on each keystroke (debounce not required for local string matching)
- Up/Down navigation arrows and Enter/Shift+Enter cycle through matches
- Current match index wraps (after last match, goes back to first)
- Clicking a matched segment still seeks the video
- Clearing the search input (X button or selecting all + delete) removes all highlights and resets match state

### Auto-scroll priority
- During video playback: auto-scroll to active segment (existing behavior)
- During search navigation: auto-scroll to current match (overrides playback auto-scroll)
- If user manually scrolls during playback, do not fight the scroll position (existing behavior)

## Accessibility Contract

| Rule | Implementation |
|------|----------------|
| Tab ARIA | `role="tablist"`, `role="tab"` with `aria-selected`, `role="tabpanel"` with `aria-labelledby` |
| Tab keyboard | Left/Right arrows switch tabs, Home/End go to first/last tab |
| Search input label | `aria-label="Search transcript"` (no visible label, icon-only) |
| Clear button label | `aria-label="Clear search"` |
| Nav arrow labels | `aria-label="Previous match"`, `aria-label="Next match"` |
| Match announcement | `aria-live="polite"` region for match count updates |
| Segment buttons | Each segment `<button>` has implicit label from text content |
| Focus management | Tab switch does not move focus; search input is not auto-focused on tab switch |
| Reduced motion | Auto-scroll uses `behavior: 'smooth'` which respects `prefers-reduced-motion` natively |
