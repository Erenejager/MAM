    - Build an updates object: start with { updatedAt: new Date().toISOString() }
    - Add title if title !== undefined, description if description !== undefined
    - Add tags as JSON.stringify(tags) if tags !== undefined

    - Re-fetch asset from SQLite (for the response), fire-and-forget partial OpenSearch update, return updated asset

    Fire-and-forget PARTIAL update after PATCH — only send changed fields to OpenSearch:
    ```typescript
    // Build the OpenSearch partial doc from exactly what changed — no re-reading transcript
    const osDoc: Record<string, unknown> = {};
    if (title !== undefined) osDoc.title = title;
    if (description !== undefined) osDoc.description = description;
    if (tags !== undefined) osDoc.tags = tags; // already an array at this point

    if (Object.keys(osDoc).length > 0) {
      opensearchClient.update({
        index: 'mam-assets',
        id,
        body: { doc: osDoc },
      }).catch((err: Error) => console.warn('OpenSearch partial update failed (PATCH):', err.message));
    }
    ```

    Why partial update instead of full re-index:
    - Avoids re-reading transcript blob from SQLite on every title/tag edit
    - Avoids sending transcript over the wire to OpenSearch
    - opensearchClient.update() with `doc` merges into the existing document
    - The full document index (opensearchClient.index()) is still used in pipeline.ts during ingest — that's the only time the full document needs to be sent
