## Component Inventory

### 1. InlineEditText

Click-to-edit single-line text field for title.

| State | Visual |
|-------|--------|
| Read | Plain text, `text-text text-sm`, `cursor-pointer`. Hover: text underline with `text-text-muted` dashed underline |
| Edit | `<input>` with `bg-background border border-border rounded px-2 py-1 text-sm text-text font-sans`. Focus: `border-cta shadow-[0_0_0_3px_rgba(225,29,72,0.15)]` |
| Saving | Input disabled, `opacity-70` |
| Success | Border transitions to `border-status-complete` for 800ms, then fades back to `border-border` |
| Error | Border transitions to `border-status-failed` for 800ms, value reverts to previous |

### 2. InlineEditTextarea

Click-to-edit auto-expanding textarea for description.

| State | Visual |
|-------|--------|

| Saving/Success/Error | Same as InlineEditText |

Keyboard: Shift+Enter inserts newline. Enter on its own saves. Escape cancels. Blur saves.

## Animation Contract

All animations use Framer Motion (framer-motion 12.x).

### Save Feedback Flash

The border flash on inline edit fields after save success or failure.

```tsx
// Framer Motion animate prop on the input/textarea wrapper
// Success: border-color transitions through green then back
// Error: border-color transitions through red then back

// Implementation: use a state variable for border color class
// and CSS transition (not Framer Motion) for simplicity:
//   transition: border-color 200ms ease-out
// Set border to success/error color, then setTimeout 800ms to revert.

// CSS classes:
// Success: border-status-complete (--tw: border-[#10B981])
// Error: border-status-failed (--tw: border-[#E11D48])
// Duration: 800ms total visible, 200ms ease-out transition in, 200ms ease-out transition out
```

Timing:
- Flash in: 200ms ease-out
- Hold: 400ms
- Flash out: 200ms ease-out
- Total: 800ms

### Autocomplete Dropdown

```tsx
// Framer Motion AnimatePresence + motion.div
initial={{ opacity: 0, y: -4 }}
animate={{ opacity: 1, y: 0 }}
exit={{ opacity: 0, y: -4 }}
transition={{ duration: 0.15 }}
```

### Settings Page Transition

No page transition animation. Settings page replaces the main content area instantly via conditional rendering (consistent with the app being a single-page tool, not a website).

### Reduced Motion

All animations respect `prefers-reduced-motion: reduce`:
- Save flash: skip animation, apply border color instantly for 800ms then revert
- Dropdown: render without animation

Implementation: Framer Motion's built-in `useReducedMotion()` hook.

## Interaction Contracts

### Click-to-Edit Flow

1. User clicks a value (title, description, or custom field value)
2. Text swaps to an input/textarea. Input is auto-focused with all text selected.
3. User edits the value.
4. **Save triggers:** Blur event OR Enter key (Shift+Enter for newline in textarea only).
5. **Cancel trigger:** Escape key. Value reverts to the original, input closes.
6. Optimistic update: UI shows the new value immediately. PATCH request fires in background.
7. On success: border flashes green for 800ms. Invalidate `['assets', id]` and `['assets']` queries.
8. On error: value reverts to previous, border flashes red for 800ms.

### Tag Add Flow

1. User clicks `+` button after last tag chip.
2. Autocomplete dropdown opens with search input focused.
3. User types; dropdown filters existing tags from cached `/api/tags` data (client-side, 150ms debounce).
4. User selects a tag (click or Enter on highlighted item) or types a new tag and selects "Create 'x'" option.
5. Dropdown closes. Tag chip appears immediately (optimistic). PATCH request fires with full updated tags array.
6. On success: invalidate `['assets', id]`, `['assets']`, `['tags']` queries.
7. On error: tag chip removed (revert).

### Tag Remove Flow

1. User clicks `x` on a tag chip.
2. Tag chip disappears immediately (optimistic). PATCH request fires with updated tags array (tag removed).
3. On success: invalidate `['assets', id]`, `['assets']`, `['tags']` queries.
4. On error: tag chip reappears (revert).

### Custom Field Definition (Settings)

1. User types field name in the input and clicks "Add Field" or presses Enter.
2. Field appears in the list immediately (optimistic). POST request fires.
3. On success: invalidate `['custom-fields']` query. Input clears.
4. On error: field removed from list, input retains the typed value.

### Custom Field Deletion (Settings)

1. User clicks `x` next to a field in the Settings list.
2. Field disappears immediately (optimistic). DELETE request fires. Cascade deletes all per-asset values.
3. On success: invalidate `['custom-fields']` query.
4. On error: field reappears in the list.
5. No confirmation dialog (per 04-CONTEXT.md decision).

### Navigation: Settings vs Library

The sidebar gains a "Settings" nav item. Clicking it sets an app-level state (`view: 'library' | 'settings'`). The main content area conditionally renders either `AssetGrid` (with detail panel) or `SettingsPage`. No URL routing needed -- state-based view switching matches the existing pattern (no react-router-dom installed).

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Focus visibility | All inline edit inputs show `border-cta` + `shadow-[0_0_0_3px_rgba(225,29,72,0.15)]` on focus |
| Keyboard navigation | Tab moves between editable fields; Enter/Escape for save/cancel; Arrow keys in autocomplete dropdown |
| ARIA: inline edit | `aria-label="Edit title"` on clickable read-mode text. Input gets `aria-label="Title"` |
| ARIA: autocomplete | `role="combobox"` on input, `role="listbox"` on dropdown, `role="option"` on items, `aria-activedescendant` for keyboard highlight |
| ARIA: tag remove | `aria-label="Remove tag {name}"` on each `x` button |
| ARIA: Settings delete | `aria-label="Delete field {name}"` on each `x` button |
| Reduced motion | `useReducedMotion()` hook disables flash animation and dropdown slide |
| Color not sole indicator | Save success/failure also reverts value (error) or keeps value (success) -- not color-only |
